⌖Dispatcher

The brain of the Gateway. Every owner intent — typed, voiced, or relayed by Telegram — lands at Agent Zero, descends through Hermes when proven, and gets resolved into a fan-out execution plan with a single audited trace ID. Engine, route, and policy decisions are made here, once.

1Intake

Owner intent

Typed, voiced, Telegram, AgentMail, or workflow trigger. Normalized into a signed Intent{} object with owner identity, scope, and proof slot.

2Resolve

Agent Zero

Commander resolves what kind of work this is, pulls Tony memory provenance, and drafts a tool/skill plan. Either executes directly or hands to Hermes for specialist work.
p5095ms
3Gate

Policy & Bridge

RBAC, scope, rate limits, Bridge Session proof. If hermes_called:false, downgrades to read-only path. Denials are first-class events.
p5028ms
4Plan

Engine + fan-out

Picks engine by capability × budget × latency × per-owner pinning. Builds fan-out tree across MCP servers, OpenCloud forks, and connectors. Token budget reserved.
p50156ms
5Execute

Run & settle

Streams worker output, settles tokens with the Governor, writes a single trace to Build-Wiki, and emits the result event back to the channel of origin.
